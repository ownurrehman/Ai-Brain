# Strategic Research & Planning (Core Practice)

**Status**: Active | **Domain**: Information / Context / Strategy | **Ownership**: Shared (Opus Standards)

Standardized research and planning practices for the AI Codes workspace. Load this during any context-heavy or strategy-heavy task.

---

## 🔍 1. Information Gathering

1.  **Read the Map**: Check **`INDEX.md`** first. Never guess where a file is.
2.  **Verify Sources**: If a file says something is true, check it (`ls`, `grep`, `view_file`) if it was written >30 days ago.
3.  **No Hallucinations**: If you can't find a file reference, ask. Never invent folder paths.

## 🗺️ 2. Planning Protocol

- **Break Down**: Any task >3 steps needs a plan in chat first.
- **Identify Risks**: Note if a task can break cross-project dependencies (e.g. changing shared Brain files).
- **Milestones**: Define "Done" clearly. (e.g. "Tests pass, README updated").

## ⚖️ 3. Decision Framework

- **Cost/Benefit**: Is a new library needed? If so, why? Can we do it with vanilla JS?
- **Architecture**: Always follow **`patterns/`** if you are moving logic.
- **Alignment**: Check **`Mastersheet.md`** for "Current Focus". Never deviate from the owner's strategic intent.

---

## 📊 Planning Quality Checklist

- [ ] Does this follow the "Mastersheet -> Protocol -> Skill" flow?
- [ ] Are we using existing patterns vs inventing new ones?
- [ ] Is this the *minimal* change for the maximum benefit?
- [ ] Is the plan visible and confirmed?
