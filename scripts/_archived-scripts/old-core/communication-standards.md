# Communication & Growth (Core Practice)

**Status**: Active | **Domain**: Output / Prose / Learning | **Ownership**: Shared (Opus Standards)

Standardized communication and feedback practices for the AI Codes workspace. Load this during any writing or reporting task.

---

## ✍️ 1. Communication Rules (The "Agent Prose")

1.  **Be Brief**: Use GitHub-flavored markdown. Bullet points > Paragraphs.
2.  **Be Direct**: State results first. Details second.
3.  **No Tics**: No "I understand your request," "Sure, I can help," or "I hope this helps."
4.  **Formatting**: Bold file names **[`FILE.md`](file:///absolute/path/to/file.md)** for readability. Use `diff` for code.

## 🔄 2. The Learning Loop (Update Protocol)

- **Failure Update**: If a plan failed or a bug was subtle, update **[`Ai-Brain/memory/lessons-learned.md`](Ai-Brain/memory/lessons-learned.md)**.
- **Success Update**: If a new pattern worked well, update **[`Ai-Brain/memory/past-wins.md`](Ai-Brain/memory/past-wins.md)**.
- **Mastersheet Update**: After major updates, the **`Mastersheet.md`** MUST be updated (Recent Significant Changes).

## 🌍 3. Cross-Platform Rules

- **Identical Rules**: Every platform (`.cursorrules`, `CLAUDE.md`, etc.) must look the same and point back to the **Master Protocol**.
- **Sync**: If you change the protocol in **`AGENTS.md`**, update the platform shims (five-line identical files).
