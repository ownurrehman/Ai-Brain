## 2. Finance PDF Service

**File:** `rankray-hq-backend/src/finance/services/pdf.service.ts`

### What it shows
- **Header:** Logo (if URL is valid and image loads), Company Name, Address, Email, Phone, Website — all lines filtered with `.filter(Boolean)` so blank lines are skipped.
- **Fallback:** If `workspace.name` is missing, shows **"Agency"**.
- **Footer:** `Generated by RankRay HQ • Page X/Y` — **hardcoded** product name.

### Issues found
| # | Issue | Severity | Details |
|---|-------|----------|---------|
| F1 | Hardcoded footer brand | Low | Footer always says "RankRay HQ" regardless of workspace. Should say the workspace name or be removed entirely. |
| F2 | Weak name fallback | Low | Fallback text `"Agency"` is generic. Should be `"Company"` or the workspace slug. |

### Verification
```ts
// createDocumentBase() — correct field mapping
doc.text(workspace.name || 'Agency', ...)
const agencyLines = [
  workspace.address, workspace.email,
  workspace.phone, workspace.website,
].filter(Boolean)
```
All NAP fields are present and safely handled. ✅

## 4. Frontend Settings Form

**File:** `rankray-hq-frontend/src/modules/settings/Settings.tsx`

### Fields collected (all present ✅)
| Field | Form control | Backend field |
|-------|-------------|---------------|
| Company Name | `name` | `workspace.name` |
| Business Email | `email` | `workspace.email` |
| Website | `website` | `workspace.website` |
| Phone | `phone` | `workspace.phone` |
| Office Address | `address` | `workspace.address` |
| Company Logo | `logo` | `workspace.logo` |
| Display Company Name | `companyDisplayName` | `workspace.companyDisplayName` |
| Legal Company Name | `companyLegalName` | `workspace.companyLegalName` |
| Owner Name | `ownerName` | `workspace.ownerName` |
| Primary/Secondary Website | `primaryWebsite`, `secondaryWebsite` | Same |
| Social URLs | `linkedinUrl`, etc. | Same |

### Issues found
| # | Issue | Severity | Details |
|---|-------|----------|---------|
| ST1 | **No form validation** | Medium | No required-field markers, no email regex, no URL validation, no max-length checks. User can save empty required fields. |

### Data flow
1. Form submits via `handleSubmit(onSaveWorkspace)`
2. `onSaveWorkspace` calls `updateWorkspace(data)` from authStore
3. `updateWorkspace` PATCHes `/workspaces/current`
4. Backend `WorkspaceController.updateCurrent` receives the body
5. Backend calls `workspaceService.update(id, rest)`

**One backend concern:** `updateCurrent` strips `isInternal` but does **not** validate or whitelist other fields. Any Prisma field on Workspace can be overwritten by a PATCH request. This is not a PDF-specific bug, but it is a security surface area.
