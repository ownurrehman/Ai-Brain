### LESSONS LEARNED (CRITICAL MISTAKES)

#### Mistake #1: Forgot Yoast Meta Fields on 11 Pages
- **What happened:** Created 11 new pages without setting `_yoast_wpseo_focuskw`, `_yoast_wpseo_title`, `_yoast_wpseo_metadesc`
- **Impact:** Pages had no SEO meta tags, would rank poorly
- **Fix:** Retroactively updated all 11 pages with proper Yoast metas
- **Prevention:** Added Yoast checklist to protocol - MUST verify before marking complete

#### Mistake #2: Attempted Image Uploads Without Explicit User Approval
- **What happened:** Downloaded and uploaded images for Knee Pain page without asking
- **Impact:** User rejected images, created friction, wasted time
- **Fix:** Stopped image handling, user took over manually
- **Prevention:** Added rule: "Never handle images without explicit user approval"

#### Mistake #3: Content Duplication in Early Pages
- **What happened:** Put bullet lists inside paragraph fields when dedicated bullet fields existed
- **Impact:** Content structure was wrong, user had to correct
- **Fix:** Fixed in later pages, separated paragraphs (narrative) from bullet fields (benefits)
- **Prevention:** Added strict rule to protocol

#### Pre-Flight Checklist (Mandatory Before Marking Complete)
For EVERY new page creation:
- [ ] Yoast focus keyword set (service + location)
- [ ] Yoast title <60 chars
- [ ] Yoast description <160 chars (KWD + LSI + Brand + CTA)
- [ ] H1 is user-friendly (Service + Benefit, NO pipes, NO location stuffing)
- [ ] Phone number in CTA section
- [ ] 10 FAQs with 150-250 char answers
- [ ] No bullet lists in paragraph fields
- [ ] Status is "draft"
- [ ] Parent is 6305
- [ ] Template is services-pages.php
- [ ] Content length ~8,000-10,000 chars
- [ ] VERIFY via API response before confirming

#### New Rule Added to Protocol:
**"NEVER create pages without Yoast meta fields in the same API call when possible. Always verify Yoast fields in the API response before confirming completion."**
