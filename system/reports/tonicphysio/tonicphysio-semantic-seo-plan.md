### 2.3 Structural Problems Identified

1. **Only 2 Blog Categories** (`guide`, `news`): This is a severe semantic signal gap. Google cannot understand the topical hierarchy of your content.

2. **No Tag System / No Tag Pages**: Zero topical tag clustering exists. Tags like "back-pain," "sciatica," "shockwave," "sports-injury" would create contextual bridges.

3. **Sub-service pages buried under `/physiotherapy-in-milton/`**: These aren't proper hub pages. They look like leaf nodes rather than cluster hubs.

4. **Blog posts sit flat under `/guide/`**: No sub-category structure like `/guide/back-pain/`, `/guide/sports-injury/`, `/guide/senior-health/`.

5. **Missing internal linking bridges**: Blog posts reference their parent service inconsistently. I found no structured "Related Content" pattern.

6. **FAQ page is generic** (not condition-specific): Every condition page should have its own FAQ schema block.

7. **No dedicated Location Pages**: Only mentions "Milton" in content. No geo-entity pages for nearby areas (Oakville, Burlington, Mississauga, Halton Hills).

8. **No E-E-A-T author entity pages for conditions**: Therapist profiles exist but don't link to "Conditions Treated" or "Specializations."

## 6. Entity Optimization: Schema Markup Strategy

### 6.1 Current State

- Using Rank Math SEO Plugin
- Previous audit found custom `@type: "physiotherapy"` which is NON-STANDARD
- No proper `MedicalClinic` or `Physician` schema

### 6.2 Required Schema Implementation

| Page Type | Schema Type | Key Properties |
|-----------|-------------|----------------|
| Homepage | `MedicalClinic` + `LocalBusiness` | name, address (Milton), geo, openingHours, telephone, priceRange, aggregateRating |
| Service Pages | `MedicalWebPage` + `Service` | provider, areaServed (Milton), description, offers |
| Therapist Profiles | `Person` + `Physician` (if applicable) | name, jobTitle, worksFor, medicalSpecialty, image |
| Blog Posts | `Article` + `MedicalScholarlyArticle` | author, datePublished, reviewedBy (E-E-A-T signal) |
| FAQ Blocks | `FAQPage` | mainEntity → Question/Answer pairs (EVERY service page should have this) |
| Condition Pages | `MedicalCondition` | name, signOrSymptom, possibleTreatment, relevantSpecialty |
| Location Pages | `MedicalClinic` + `Place` | sameAs (Google Business Profile), geo, maps link |

### 6.3 E-E-A-T Signals to Add

1. **Author boxes** with credentials on every blog post (already have therapist profiles)
2. **Medical review attribution** on medical content: "Reviewed by [RPT Name], Registered Physiotherapist"
3. **"Last Medically Reviewed" date** on all condition/service pages
4. **Google Business Profile** linked via `sameAs` in schema
5. **Awards markup** (Quality Business Award 2025, Diamond Winner 2024)
